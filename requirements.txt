# The built-in note writer. Runs a GGUF inside this process, so a summary needs
# no second program installed -- which is the whole reason it is here.
#
# Not on PyPI as a wheel: PyPI carries an sdist only, and building it needs a
# C++ toolchain no user is going to have. The maintainer publishes prebuilt
# wheels on their own index, which the bundler passes with --extra-index-url.
# They are tagged py3-none-<platform> rather than cp312: the C++ lives in a
# shared library loaded through ctypes, not in a CPython extension, so one
# wheel works on any Python 3.
#
# The marker excludes macOS on Intel, which has never had a py3-none x86_64
# wheel -- the newest usable build there is 0.3.2. That platform falls back to
# the CTranslate2 engine, which ships anyway as a transitive dependency of
# faster-whisper. Without the marker, pip would find no wheel there and try to
# compile the sdist, and the build would fail on the build machine rather than
# quietly on a user's.
#
# NOT SHIPPED IN 1.2.3, and the line is kept rather than deleted because the
# reasoning above is still correct and this comes back the moment the built-in
# note writer does.
#
# Two reasons to leave it out, and either would be enough on its own.
#
# It has no user. `SHOW_BUILTIN_NOTES_ENGINE` is False, so nothing in the app
# can select the engine this exists for. Shipping 40 MB of runtime for a code
# path no user can reach is not a trade, it is just weight.
#

# known-vulnerable package is a poor thing to ship at the best of times; doing
# it for a feature that is switched off is indefensible.
#

# markupsafe in constraints.txt, and checking whether PYSEC-2026-2447 has a fix
# by then.

# --- Why these are pinned, not floored -------------------------------------
# `>=` floors meant an identically-named build could contain different code
# depending on the day it was built. That broke three things at once:
# reproducibility, the ability to answer "is version X affected by CVE-Y", and
# the accuracy of the SBOM the moment it left the builder.
#
# These versions are not "latest" -- they are exactly what the published v1.2.0
# resolved to, read back from its own CycloneDX SBOM. Pinning to latest would
# have changed the software; pinning to the shipped set changes only whether it
# can be rebuilt.
#
# Install the full locked set, transitive dependencies included, with:
#     pip install -r requirements.txt -c constraints.txt
#
# When bumping: change the pin, rebuild, and re-read the SBOM so constraints.txt
# and this file continue to agree.
